## PASS 1

## Proximity project

Create a docker container named Proximity what allow route outgoing network
connections from host to a number of outgoing connections by domain/IP/geo
basis as it possible with mihomo app and number of outgoing host/VPN/proxy
connections.

Naming used:
* project: Proximity;
* docker name: proximity;
* container: proximity;
* image name: proximity;
* network interfaces: proximity_<lan>;
* other identifiers: proximity_<id>.

Proximity mast store all it configuration (settable parameters, any data what
should not be lost between reboots) in the internal "config" folder what
exposed to host into "$HOME/.config/proximity" on Linux (and similar
directories on MacOS/Windows);

Proximity should allow to login a number of users. Each user have a
different access levels:
* Administrator - all access;
* Operator - edit configuration;
* User - view only;
* Anonymous - only dashboard view;

On a first start Proximity should create a new Administrator user.

Docker should expose a Web-UI on port 8899.

UI consists of:
* header: logo, short statistics, actual user logged in;
* left column: navigation between section;
* center pane: pane with a view of selected section;
* footer: version copyright, page generation time.

Left navigation pane have the following sections order:
* Dashboard
* Endpoints
* Fallbacks
* Filters

Start with Dashboard selected.


## UI: Endpoints sections

endpoint is an outgoing internet connection what can be provided by user.

Initially endpoints should can have the following types:

* HOST Internet: an internet from the host system. configured by selection
  outgoing internet connection:
    ** default host routing
    ** specific host Ethernet interface
    ** so on, as it possible to be configured...

* SOCKS5 Proxy: Connection to SOCKS5 server.
  Configuration parameters ("SOCKS5 Proxy) page:
    ** server IP address or hostname;
    ** port (with default value);
    ** optional username;
    ** optional password;
    ** something else a can forget.

* HTTP Proxy: Connection to HTTP/HTTPS/FTP proxy server.
  Configuration parameters ("HTTP Proxy" page):
    ** server IP address or hostname by protocol;
    ** port by protocol (with default value);
    ** allow use single HTTP IP:port for all protocols;
    ** optional username;
    ** optional password;
    ** something else a can forget.

* OpenVPN: connects to OpenVPN server.
  Configuration parameters ("OpenVPN" page):
    ** VPN configuration file (uploadable and editable within UI);
    ** optional user name;
    ** optional user password;
    ** optional OTP key to generate challange answer with oathtool;
    ** enable monitoring ("Monitoring page):
      * monitoring enable flag;
      * pings default gateway obtained from VPN each <N> seconds;
      * wait for response for <N> seconds;
      * if ping fails, repeat ping <N> times>;
      * if repeat fails, reconnect after <N> seconds, <N> times;
      * if reconnect fails, down OpenvVPN connection and mark as failed.
  The connection should be established by starting openvpn client and
  interception of the it prompts with tools like Python pexpect.

  OpenVPN connection can provide number of routes (via 'ip route show')
  what should be exposed to the Router Service as subset of read-only, but
  viewable filters what can be activated in Routing Table.

* AmneziaWG: Connection to AmneziaWG server.
  AmneziaWG parameters:
    ** configuration file editable within UI;
    ** optionally allow to scan QR-code from provided image to read
       configuration.
    ** enable monitoring ("Monitoring page):
      * enable flag;
      * check connection with server (how - select you self);
      * wait for response for <N> seconds;
      * if ping fails, repeat ping <N> times>;
      * if repeat fails, reconnect after <N> seconds, <N> times;
      * if reconnect fails, down AmneziaWG connection and mark as failed.

Each endpoint should have:
 on "General" page:
 ** ID - unique string allocated automatically then creating endpoint or
    can be passed by user, default ("<type> <N>", where N is a decimal
    number);
 ** Name - some text string identifies endpoint name;
 ** Group - new or existing group (group is a string);
 ** Enable flag - user can enable/disable endpoint;
 ** Collect statistics - compute number of outgoing and inbound traffic;

List of endpoints should be fully configurable by user (operations like
add, edit, delete). Any changes to endpoints configuration mast influence
on router service and changes going to work immediately.

Table of endpoints in UI should be able to move endpoints positions up
and down, positions should be saved in configuration.

UI dialog for creating/editing endpoints should consists of:
* "General" tab;
* "<Endpoint>" tab, named by endpoint type;
* optional "Monitoring" page;


## Router service

Router is an internally mihomo service what exposes connection to the host
system and allows routing sites by number of manually defined conditions
(domains, IP, IP:port and so on) to configured proxy groups.

Router service is configured via Filters and Fallbacks UI.

Proximity should monitor and parse messages from mihomo. Collect
unaccesible routes (for exapmle with messages "connect: connection refused"
or "connect: connection timed out" or something like what) and maintain a
list of refused routes/ips/domains on the Dashboard page.


## UI: Filters section

Proxy group (named Fallback, see Fallbacks section) consist of one or more
mihomo's proxy. Each proxy - preconfigured Endpoint from Endpoints section.

Router service UI should be able to create, edit and delete a number of
filters. Each filter have the following parameters:
  * ID - optional name
  * Directive: one of the following: DOMAIN, DOMAIN-SUFFIX, DOMAIN-KEYWORD,
    GEOIP, GEOSITE, IP-CIDR, PROCESS-NAME and so on;
  * Target: drop down list of Endpoints and Fallbacks, single selection.
  * Rule parameters, multi-line edit;

Each filter is translated to lines for mihomo configuration:

  <Directive>,<Rule parameter>,<Target>

Rule parameters should be checked for format and properly converted, for
example:
  * rule parameters for DOMAIN, DOMAIN-SUFFIX, DOMAIN-KEYWORD should not
    contain reserved characters;
  * if rule parameters for IP-CIDR have an IP:port format, it should be
    converted to "ip==<IP>/32 and port==<PORT>" IP-CIDR rule, if IP have
    no mask, mask = 32 mast be added and so on.

Filters should be moveable up and down by user. Rearranged filters should
be saved, moihomo configuration regenerated and applied.

Filters should be checked for consistence, for example, for duplicate IP's,
intersected networks and domains. Editor should allow to enter an
inconsistent parameters, only inform user (by warning at the top the pane).


## UI: Fallbacks section

Fallback is a proxy group for mihomo. Fallbacks should be configurable in
separate UI section. User should be able to create, modify and delete
Fallbacks. Each Fallback consists of the following:
  * ID - optional title string (default "Fallback <N>")
  * enable flag;
  * List of Endpoints: managed modifiable list of available preconfigured
    Endpoints;


## Implementation details

UI should use some modern UI interface. Each dialog (create, modify and so
on) should check parameters provided by user for validity before accepting
them. UI can partially behave to 3x-ui (https://github.com/MHSanaei/3x-ui);

Add favicon, Proximity logo image (create one), add modern icons to
navigation panels, sections, toolbars, dialog pages, etc...

Select the simplest way to connect Endpoint to mihomo as a proxy. Prefer
to use of non-interruptable connection (like SOCKS5, TCP/IP) rather than
request based ones (plain HTTP). Connection should be able to monitor it
status: actual link status, connectivity based on endpoint type, operation
status (good, reconnecting, fail). For best results add monitoring for
traffic.

## UI: Dashboard section

Dashboard should consists of a general status of the Proximity operation.
For example, number of Endpoints, Fallbacks, Filters.
Table with state for each endpoint: status (enable/disable/unused), link
status, income/outgoing bytes and so on.
